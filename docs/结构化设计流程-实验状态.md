# 结构化设计流程（实验状态）

2026-11-16：实现与首轮验证完成，**默认未启用**。九图对照没有证明新版在海报、Logo、背景三个场景都优于原文直连或现行优化，因此不替换正式规则。测试通过不代表视觉质量通过。

## 入口与数据流

- 默认：使用 `buildSystemSpec` / `buildVisualPromptRules`；2026-11-16 后续调整为原意优先整理，详见《原意优先的提示词整理》。
- 实验：启动 Bridge 时显式设置 `HUIBAN_VISUAL_DESIGN=1`；节点与对话同时走新流程。删除此环境变量并重启即可回到现行规则，无数据迁移。不要仅因构建通过就启用。
- 离线测试可给 `enhancePromptDetailed` 传 `planningMode: 'design'`，或以 `'legacy'` 固定走非结构化入口，不修改用户设置、不重启服务。`legacy` 使用当前默认规则，不是冻结的旧版规则；复现首轮对照需使用当时保存的源码和提示词。HTTP请求不允许直接覆盖实验开关。

节点：当前配置的语言模型产出 `design` → 本地校验 → 必要时同一路语言模型核对一次 → 编译最终提示词 → 原生图链路。

对话：当前线程Agent通过 `generate_image.design` 提交方案 → 同一校验与编译器 → 原生图工具。不会再把Agent最终提示词交给另一套优化规则重写。普通回复、澄清、记忆、预算与用户确认仍按原运行循环处理。

## 中间结果

`bridge/visualDesign.ts` 定义结构及纯函数：

- `requirements`：原文出处与约束解释。编译时采用原文出处，防止模型在解释中扩大禁止项。
- `exactText`：必须逐字呈现的文字。
- `copy`：原文片段与可整理的最终画面文案。
- `openDecisions`：需要设计者解决的事项；不发给生图模型，不代表应向用户追问。
- `visual`：一个已确定的构思、视觉重点、构图、表现方式、图文层级，以及编辑边界。
- `references`：每张实际图片的用途；图片编号保持用户原始顺序。

`compileVisualDesign` 只编译实际执行内容，不将整个JSON、思考过程或自评分发送给生图模型。返回结果包含 `design` 与 `planning` 元数据；对话将其保存于工具记录。节点接口返回这些字段，但现有前端没有增加展示或完整持久化入口。

## 有界检查

本地检查：结构、出处、固定画幅、参考编号、数值、逐条文案的部分条件（如单张、整本、每日、每人、概率、数量上限）、重复文案。

复杂文本、多图、较多画面文案、检测到未定选项，或本地校验失败时，再用同一语言配置核对一次。核对可返回最小修正版；修正后仍不合格就抛错，禁止当成成功优化。节点调用方保留原有带原因回退策略；Agent在生图请求前终止并报错。

“一次核对”指一个逻辑核对阶段。底层现有协议回退、截断后扩展输出预算可能产生额外HTTP请求，不代表绝对最多两次网络请求。网络失败不在此层无限重试。

## 首轮结果与限制

- 同一非公司生图配置、同一模型与quality参数，海报/Logo/背景各做原文、现行、新版三组，共九张，全部成功。逐字核实实际发送的提示词，按文件头核实实际图片尺寸。
- 新版Logo更明确表达了山与信的关系；背景未显示稳定优势；海报仍为常见红金促销形式，并出现条件遗漏、日期重复和仿真二维码。不能据此宣布总体质量提升。
- 增补的本地检查可以拦住海报文案中遗漏“单张”及日期重复；真实核对模型仍有未修复项，程序正确拒绝，不把此结果送去继续生图。补检查后的版本没有额外生成第十张图片。
- 新版语言阶段明显增加耗时，且出现超时、524及结构协议不遵循。复杂需求的追加核对不是免费的质量保证。
- 六类文字样本覆盖海报、Logo、背景、产品、多图参考、连续编辑。产品/多图/连续编辑只检查文字与路由，没有额外成图验证；多图在第一次核对超时后复用了已保存草稿重新核对，不能计作首次端到端成功。
- 检查只覆盖部分可识别条件，不能验证全部事实关系、审美或图片中文字。模型自查可能漏错或误判设计自由，仍需人工看图。
- 新任务模式可以阻止实际生图继承旧图，但用于判定任务的Agent仍可能看见旧视觉工作集；本次没有完成独立的语义上下文路由。
- 每组一张，无固定种子；请求的模型名与quality只是供应商参数，不构成底层模型身份或执行质量证明。

## 下一轮的检验重点

根据用户对 Logo 与背景的复评，停止把“概念更明确”视为质量提升。当前先改默认规则为保留原意、补必要信息，不再要求语言模型为所有任务补齐视觉方案。本结构化实验继续关闭，不增加设计轮次或核对调用来替代成图质量证据。

只有在多类样本中同时改善需求忠实性和视觉表现，并复测后，才考虑切换默认流程。不得拿单个成功Logo或回归测试结果替代该门槛。
