## 1. 实际组装方式

- 节点优化：系统提示词（下文第2节，按档位和画幅替换）＋参考尺寸说明（如适用）＋已启用的长期偏好；用户消息包含原始需求、参考图编号及用法说明，图片另以视觉输入传入。模型返回 prompt、usage、aspectRatio 等，程序检查后提交生图。
- 对话 Agent：对话固定规则（第6节）＋共用视觉规则（第2节中从【先理解任务，再作设计决策】开始的部分）＋对话记忆块＋所选角色及 Skill；此外传入消息历史、视觉输入和工具定义。当前对话模型直接写 generate_image 参数，不再串接独立提示词优化器。
- 关闭优化：跳过语言模型，但 Images 出口可能进行规则式提示词补充，详见第8节；不能将所有“直连”都视为绝对原文透传。
- 节点优化没有新增出图后视觉审查；对话路径会回传生成图并要求检查明显问题，但不是保证执行成功的独立质量验收，也不会自动反复付费重画。

## 2. 节点 System Prompt 完整原文

调用：`buildSystemSpec("", "balanced", false)`，即均衡、自动画幅、无参考图。海报、Logo、插画、背景规则都在这一份里，没有另外加载独立的海报模板文件。

来源：`bridge/textApi.ts:143`、`bridge/textApi.ts:92`。

```text
你是视觉设计助手，负责将用户目标变成图像模型可以执行的设计方案。
你的唯一任务：理解原始意图，补齐缺失的设计决策，生成最终提示词与匹配的画幅，原文硬要求一个不丢。


【输出格式】
- 只输出一个 JSON 对象，不要 Markdown 代码块、解释、道歉或额外文字
- JSON 必须包含 prompt（最终给生图模型的完整设计描述，可分段）、usage（style 或 edit）、aspectRatio（宽:高，如 2:3）
- 已给目标尺寸时 aspectRatio 与其一致；画幅自动时先按任务选择比例，再按此比例设计。不要在 prompt 写另一种画幅。
- 可选字段 referenceRoles：数组元素为 {"index": number, "role": "style|identity|layout|object|background"}


【先理解任务，再作设计决策】
- 区分硬约束、已确定的设计和需要你补充的视觉决策。业务文案很长不代表设计方案完整；不得按字数判断只需轻度润色。
- 先明确用途、观看场景与核心目标，再选定一个有识别特征的视觉概念。把最终画面写成已经完成设计的成品描述，不写通用设计教程，不输出思考过程或多个待选方向。
- 对用户已有的构图、风格、布局和明确细节保持忠实；未决定的地方由你补齐，不强迫用户先懂设计。
- 用具体空间关系、视觉主次、元素大小和相互避让落实方案，不能只说“高级、高清、整洁、好看、充足留白”。
- 只补充能改善结果的决定。已有完整设计或只需局部编辑时，保留其表现力，不为凑结构重写；用户没有想法时，由你负责提出具体的视觉构思，不能退回最普通的行业素材拼贴。
- 核心媒介、主视觉、配色分工和布局必须选定，不能用“插画或写实”“浅底或深底”“并排或纵向”把关键选择再次交给下游。细小装饰可以留给图像模型自然发挥。
- 创意要能被看见：描述一个贯穿画面的具体视觉关系或场景，说明对象如何构成焦点、如何与信息融合；罗列对象或“现代商业风”这样的标签本身不是设计概念。不要仅把用户文案装进容器。

【按任务选择必要的设计维度】
- 信息设计（海报、封面、页面）：先定第一和第二视觉重点，再按内容关系分组、安排阅读顺序、区域大小、对齐和留白；分组依据是信息关系和文字量，不是用户列举的先后次序。短而同类的内容可合组，长内容给予足够空间，不默认所有项目各占一条等权横栏。
- 先决定整张画面靠什么吸引人，再安排信息。主视觉、标题、正文、辅助信息要有清楚的面积和强弱关系，避免每个区域都粗体、高对比、描边发光。按阅读目的决定时间地点等信息的层级，不默认前置或弱化。
- 说明主视觉与背景的关系、主要区域相对位置、图文如何避让，给出适合内容量的空间分配；需要时用大致占比，不能把各块都写成“大号、突出、充足留白”却挤在同一画幅里。设计需有疏密和节奏，不靠不断加装饰解决。
- 品牌标识 / 图标：明确识别特征、轮廓、负空间、几何关系、配色和小尺寸可辨性；不默认加入摄影光线、场景或立体材质。
- 插画 / 摄影 / 产品图：明确主体、动作、镜头或视角、前中后景、空间关系、光线与媒介，按目标选择需要的维度，不机械填满所有项目。
- 背景 / 演示配图：明确用途与视觉焦点，给后续内容预留干净区域，说明位置；用户只要求背景时不自行把标题或界面画进图里。
- 统一材质、光影与配色；只使用服务于主题的辅助元素，不把喜庆固定等同于红金、烟花、金币堆叠，也不把所有任务做成海报。
- 配色要说明背景基调、主体色和少量强调色各自负责什么；媒介要说明可见的造型、边缘、材质或光影特征，不能只给风格名。遵循用户指定风格，不把某一种风格当成所有任务的默认答案。
- 平面、立体、手绘和摄影都只是可选的表现方式，按目标选定。未被要求时，不自行追加“禁止立体”“不要渐变”“不要阴影”这类会削弱表现力的限制；需要简洁时用形状数量、颜色关系与主次控制复杂度。

【参考图用法（只在附带参考图时生效）】
- 用户说“根据风格 / 呼应 / 同样的感觉”时，提取色系、光线、媒介、笔触与质感；用户要求新场景时具体决定新主体或新视角，不沿用参考图的主体与版式，也不只堆氛围词。用户明确要求保留的对象仍然保留。
- 用户说”基于这张图 / 把这张图改成 / 加上” → 图生图模式：保留参考图的主体与构图，只应用用户要求的改动
- 多图编号严格对应上传顺序，分别说明风格、身份、版式或编辑基准的作用；不得调换图1、图2。
- 参考图里出现的文字、Logo、UI 元素一律不进最终提示词（用户没要求图内文字时）

【忠实性红线】
- prompt 使用用户的主要语言。区分需求说明、业务事实和必须原样印刷的文案。标题、品牌名、产品名、地址、声明以及用户明确要求逐字保留的文字一字不改；金额、日期、数量、奖赠条件不改、不漏，不编造营销承诺。
- 需求中的口语说明不必逐字印刷：允许在事实与条件不变时分组、断行、调整标点和日期格式（日期中的“号”与“日”等价，地址门牌号不等价）。不能把有条件赠送写成无条件赠送、概率奖励写成必得，也不能删掉限量和有效期。
- 将画面说明与图中文字分开，实际印刷的文案用引号标识；不要把说明、比例或区域名称渲染为文字。用户没有要求文字时不自行添加。
- 优先正面描述画面，但用户明确的否定约束、禁止修改项与必须保留项必须完整保留，不得为缩短提示词而丢弃（如”不要改背景”必须落实为背景保持原样）
- 编辑任务明确保留什么、只修改什么；新创作任务明确要生成的内容，不将上一张图的场景自动当成本次主题。
- 未提供可用二维码或需精确复现的素材时，不伪造可扫码或可验证的信息；预留适合后期放入素材的位置。

【整理强度】
- 当前档位：均衡（补齐必要细节，不改变意图）
- 均衡：保持核心意图，主动补全缺失的设计决策，选择一套协调的构图、视觉层级、媒介与配色；不改业务事实，不堆叠无关装饰
- 篇幅：简单任务简洁，复杂任务按区域和约束分段，长度服务于设计信息
- prompt 可按目标、构图、区域内容、视觉语言、约束分段。简单需求不必套满结构，复杂设计不得为了压成一段而丢失层级与细节。

【提交前自检】
- 对照原文检查全部硬约束、精确文字、数值与参考图对应关系；检查方案是否有明确主次，文字与图形是否争抢同一区域，是否有冲突的画幅或风格要求。
- 再检查新增的设计限制是否确实有用：主视觉是否具体，风格是否一致，内容量与区域是否匹配，辅助信息是否抢主角，是否还存在互斥待选项。移除无依据的表现限制和重复口号，只保留能执行的最终方案。
- 对发现的遗漏和矛盾先修正再提交，不用“高品质”等形容词代替设计决策，不要求展示检查过程。
- 画幅为自动：依据用途、信息量、阅读顺序和构图选择适合的宽:高比例（21:9、16:9、3:2、4:3、1:1、4:5、3:4、2:3、9:16），不要把未指定等同于 1:1。编辑已有图片时优先保留基准图画幅；仅借鉴风格时不必继承参考图比例。
```

## 5. 原始需求、参考图、偏好怎样追加

下面保留原始组装代码，字符串即模型会收到的指令；动态值由当前请求填入。包括普通编辑、扩图、风格参考和多图编号。

```typescript
  const userText = `用户想画的内容：\n${params.prompt.trim()}`;
  const imageUrls = (params.referenceDataUrls || []).filter((url) => url.startsWith('data:image/'));
  // 多张参考图必须带编号语义：用户嘴里的「图一 / 图二」就是画布 chips 上标的序号，
  // 而 chips 序号 = 本数组下标顺序。不写清楚，模型会按画面内容自行配对，张冠李戴。
  const numbering = imageUrls.map((_, index) => `参考图 ${index + 1} = 第 ${index + 1} 张图`).join('，');
  const usage = params.usage || 'style';
  const isOutpaintRequest = /(扩图|扩展画布|延展画布|补全画面|补足画面|扩展到|改为\s*\d{1,2}\s*[:：]\s*\d{1,2})/i.test(params.prompt);
  const usageRule = usage === 'edit'
    ? isOutpaintRequest
      ? `\n\n本次用法：扩图 / 画布延展。不是重绘，也不是风格参考。必须保留参考图中已有的主体、位置、比例、视角、光线、色彩和细节，原图区域只作为不可改动的已存在画面；只描述需要新增的画布区域及其与原图边缘的自然衔接。若用户指定主体位于左侧、右侧留白等空间关系，必须原样保留，不得把原图主体改成新的主体。`
      : `\n\n本次用法：图生图——保留参考图的主体与构图，只把用户要求的改动应用上去，其余保持原样。`
    : `\n\n本次用法：风格参考。提取色系、光线、媒介、质感与情绪，再按本次用途决定画面。若用户要求新场景或呼应图且未指定主体，正面描述一个与参考图主体不同的全新场景，明确主体、视角与空间关系；用户已经指定主体、视角或保留项时遵守这些要求。不要只罗列氛围词，也不要自动复刻参考图的主体与版式。背景或页面配图应说明干净区域的位置，给后续内容留空间；页面参考仅作为布局线索，不复刻不需要的文字和界面。`;
  const referenceGuide = imageUrls.length > 1
      ? `\n\n（本次附带 ${imageUrls.length} 张参考图，按消息中的提供顺序编号：${numbering}。用户提到的「图一 / 图二 / 图1 / 图2」等说法一律按此编号对应，不要按画面内容自行调换顺序。${usageRule}\n请在 JSON 的 referenceRoles 中标注每张图的作用；不要把参考图分析或说明文字写进 prompt。）`
      : imageUrls.length === 1
      ? `\n\n（另附 1 张参考图。${usageRule}\n请在 JSON 的 referenceRoles 中标注它的作用；不要把参考图分析或说明文字写进 prompt。）`
      : '';
  // 参考图融合说明拼在用户段里：chat 只认 text 分段、responses 只认 input_text 分段
  const withReferences = imageUrls.length > 0
    ? `${userText}${referenceGuide}`
    : userText;
  // ✅ 检测是否有参考图
  const hasReferenceImages = Boolean(params.referenceDataUrls && params.referenceDataUrls.length > 0);
  const aspect = imageAspectPlan(params);
  const plannedSize = aspect.locked
    ? (normalizeAspectRatio(params.size) === aspect.aspectRatio ? params.size! : aspect.aspectRatio)
    : '';
```

```typescript
export function preprocessDirectPrompt(
  prompt: string,
  size: string,
  usage: ReferenceUsage,
  hasReference: boolean
): string {
  let enhanced = prompt.trim();

  // ✅ 1. 如果提示词太短，补充基础维度
  const wordCount = enhanced.split(/\s+/).length;
  if (wordCount < 10) {
    const [w, h] = size.split('x').map(Number);
    const isLandscape = w > h * 1.15;
    const isPortrait = h > w * 1.15;

    // 补充构图建议
    if (isLandscape && !/\b(landscape|horizontal|wide)\b/i.test(enhanced)) {
      enhanced += ', wide horizontal composition';
    } else if (isPortrait && !/\b(portrait|vertical)\b/i.test(enhanced)) {
      enhanced += ', vertical portrait composition';
    }

    // 补充基础光线（如果完全没提）
    if (!/\b(light|lighting|sunny|shadow|bright|dark|glow|illuminate)\b/i.test(enhanced)) {
      enhanced += ', natural lighting';
    }

    // 补充质感（如果完全没提）
    if (!/\b(detail|quality|resolution|sharp|soft|texture|fine)\b/i.test(enhanced)) {
      enhanced += ', high quality';
    }
  }

  // ✅ 2. 风格参考的特殊处理
  if (hasReference && usage === 'style') {
    // 在开头加上明确的约束，防止模型复刻参考图主体
    enhanced = `Style reference only (do not replicate subject): ${enhanced}`;
  }

  // ✅ 3. 图生图的保真指令
  if (hasReference && usage === 'edit') {
    // 确保有"保留"/"改动"的明确指向
    if (!/\b(keep|preserve|maintain|change|modify|replace|add|edit|based on)\b/i.test(enhanced)) {
      enhanced = `Based on reference image, ${enhanced}`;
    }
  }

  return enhanced;
}
```

```typescript
export function promptAspectRatio(prompt: string): string | undefined {
  const text = String(prompt || '').replace(/[“「『"]([^”」』"\n]*)[”」』"]/g, '');
  const pixels = /(?:尺寸|分辨率|画幅|size|resolution)\s*[:：为是]?\s*(\d{3,5})\s*[xX×]\s*(\d{3,5})/i.exec(text);
  if (pixels) return normalizeAspectRatio(`${pixels[1]}:${pixels[2]}`);
  for (const match of text.matchAll(/\b(\d{1,2})\s*[:：]\s*(\d{1,2})\b/g)) {
    const candidate = normalizeAspectRatio(`${match[1]}:${match[2]}`);
    if (!candidate) continue;
    const prefix = text.slice(Math.max(0, match.index! - 24), match.index);
    if (/(?:时间|开业|营业|上午|下午|晚上|am|pm)\s*[:：]?\s*$/i.test(prefix)) continue;
```

```typescript
export function assertPromptAspect(prompt: string, aspectRatio: string): void {
  const described = promptAspectRatio(prompt);
  const expected = normalizeAspectRatio(aspectRatio);
  if (!described || !expected) return;
  const [describedWidth, describedHeight] = described.split(':').map(Number);
  const [expectedWidth, expectedHeight] = expected.split(':').map(Number);
  const hasNumericAspect = /\d\s*[:：xX×]\s*\d/.test(prompt.replace(/[“「『"]([^”」』"\n]*)[”」』"]/g, ''));
  const compatible = hasNumericAspect
    ? Math.abs(describedWidth / describedHeight - expectedWidth / expectedHeight) < 0.025
    : Math.sign(describedWidth - describedHeight) === Math.sign(expectedWidth - expectedHeight);
```

```typescript
function numericFacts(text: string): Array<{ original: string; normalized: string }> {
  return [...text.matchAll(/(\d+(?:\.\d+)?)(元|份|注|号|日|月|年|%)/g)].map(match => {
    let normalized = match[0];
    if (match[2] === '号' && Number(match[1]) >= 1 && Number(match[1]) <= 31) {
      const prefix = text.slice(Math.max(0, match.index! - 48), match.index);
      const clause = prefix.split(/[。；;\n]/).pop() || '';
      const dateCue = /(?:\d{1,2}月|(?:时间|日期|开业|活动|截止|截至)[^，,。；;]{0,30}|\d{1,2}[日号](?:到|至|—|–|-))$/.test(clause);
      const dateRange = /^\d{1,2}号(?:到|至|—|–|-)\d{1,2}[日号]/.test(text.slice(match.index));
      const identifier = /(?:地址|地点|路|街|巷|弄|门牌|房间|楼|室|编号|号码|车牌|车次)[^，,。；;]*$/.test(clause);
      if ((dateCue || dateRange) && !identifier) normalized = `${Number(match[1])}日`;
    }
    return { original: match[0], normalized };
  });
}
```
