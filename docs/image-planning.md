# 图像设计编排

智能生成先理解用途与硬约束，再补充具体设计决策，最后将提示词与画幅一起提交。节点优化器和对话 Agent 共用 `bridge/textApi.ts` 的视觉规则；对话不再额外调用独立优化模型。

## 画幅

- 节点显式比例、手动选择和扩图尺寸保持优先；继续编辑默认沿用基准图画幅。
- 节点选择“自动”且开启优化时，临时尺寸不再作为固定方形注入模型。优化接口返回 `{ prompt, usage, aspectRatio }`，前端按选定的分辨率重新计算实际请求尺寸，并更新运行态与生成记录。
- 画幅自动时，参考图尺寸是线索；仅借鉴风格不强制继承比例。编辑请求仍保留基准尺寸。
- 上游没有返回比例或优化失败时，明确比例优先，再按用途作有限兜底：演示配图偏横幅、海报偏竖幅、Logo / 图标偏方形；无法判断时才使用参考尺寸或默认尺寸。这不是海报模板，也不是模型判断的替代品。
- 对话 Agent 主动填写 `generate_image.ratio`，不再收到配置默认方形的强制构图指令。多图确认与实际请求使用同一画幅。
- 关闭优化的直连仍使用既有画幅规则。

## 设计与约束

- 不再用“输入超过40词”判断设计已完成，也不把输出限制为一段60–180词。复杂任务允许按区域和层次分段，输出预算随输入增长并设上限。
- 保留已有设计；补齐尚未决定的主次、阅读顺序、空间关系、媒介和留白。不同用途使用相关设计维度，不为所有任务加摄影光线或促销装饰。
- 高遵循、均衡、创意控制补充设计的自由度。优化模型温度分别为0.2、0.6、0.85；它们不是图像模型质量档位。上游不支持温度时沿用原有兼容重试。
- 提交前由模型核对精确文字、硬约束与参考图编号。程序另外检查可识别的画幅冲突，以及带单位的金额、日期、数量等数值遗漏；这不是完整语义验证或OCR，不能保证成图文字正确。
- 节点优化异常沿用已有回退和错误提示，不将无效结果当优化成功；对话工具发现冲突时在付费生图前报错。
- 对话已经回传的图片用于检查明显缺陷，有问题简短如实说明，不自动追加付费重绘。节点路径没有新增生成后视觉模型调用。

## 2026-11-16 诊断与修正

- 日期中的“17号”与“17日”允许规范化；地址门牌、编号仍严格比较。数值检查只验证可识别的数值是否保留，不验证金额与条件的语义对应关系。
- 独立图片优化器的输出预算为8192–16000 tokens，包含上游的思考消耗。只有明确返回 `finish_reason=length` 或 `incomplete_details.reason=max_output_tokens` 时，才允许同一文本协议扩大到16000重试一次；过滤、未知不完整和网络失败不触发这条重试。不接收截断的最终提示词。
- 该预算恢复只由独立图片优化器启用；对话 Agent 仍尊重用户配置的对话输出上限。对话与节点共用设计规则，不新增二次优化调用。
- 视觉规则区分必须逐字印刷的文字与口语需求，要求选定具体媒介、视觉概念和内容分组，并检查新增限制是否有益。没有固定为海报、红金配色或3D风格。
- 网络错误区分语言模型响应中断、生图请求结果未知、图片已生成但下载中断。下载沿用本次生成的取消与超时信号，外层不得覆盖下载阶段的错误。
- 生图请求在明确连接建立失败时可以重试；连接重置、响应超时等结果不明的传输错误不自动再提交付费生图。HTTP状态码的既有重试策略不变。

本轮经用户授权进行了3张真实对照，使用同一非公司供应商、模型别名、1024×1536、high、无参考图：原文直连、GPT优化、DeepSeek优化，各一张，均成功。另实际调用两路语言模型测试独立优化和Agent工具参数；没有执行Agent返回的生图工具。

结论：修正后的输出比例与内容组织更可控，但本轮优化版仍会落入通用促销风格，不能据此宣称优于直连或达到用户认可的复现结果。额外一轮文字审校没有稳定改善，且一次DeepSeek审校在8192输出预算下仍截断，因此没有上线双重审校。Logo、演示背景仅做提示词测试，未生成图片，不代表这些场景的成图质量已经验证。

真实请求与响应摘要保存在本机数据目录的 `experiments/prompt-quality-20261116`，不提交用户业务内容、媒体、密钥或完整运行日志到仓库。单次样本不能排除随机波动；第三方模型别名不证明实际底层版本，也无法用本次实验还原ChatGPT网页端的内部流程。

## 2026-11-16 规则审查后的最小改造

- 替换共用视觉规则，区分业务事实、用户明确要求、已确认偏好与模型自行作出的设计决定。模型确定视觉方向、重点和关键空间关系，局部纹理、装饰姿态等留给图像模型；不要求每个任务套用卡片、区域占比或同一种材质。
- 高遵循、均衡、创意分别描述设计决策权限，继续共用核心规则。保留原有温度与输出预算，没有因为中转模型别名推断其推理配置。
- 参考图编辑默认保护未要求修改的文字、Logo、UI、主体、构图与背景；明确的修改要求优先。每张参考图的用途必须写进最终提示词，不只放在可选的 `referenceRoles` 中。独立优化器和 MCP 附加说明同步调整，避免仍注入相反要求。
- `preprocessDirectPrompt` 仅去除首尾空白，不再根据空格词数或英文关键词补充自然光、高清、画幅等内容。该旧分支并非所有浏览器请求都会经过，不能将其视为此前质量差距的唯一原因。参考图编号、上下文与已有的参考图用途说明仍可能由调用方加入，完整输入以请求日志为准。

### 实际生图请求日志

位置：数据目录的 `logs/image-requests.jsonl`。在实际 JSON / FormData 请求体完成后记录，覆盖浏览器、对话和 MCP 的 Images / Responses 出口，以及重试与协议回退。约10 MiB时轮换，只保留一个 `.1` 旧文件。

记录调用方提供的 `originalPrompt` / `optimizedPrompt`、实际提交的 `actualProviderPrompt`、供应商与模型、真实尺寸和质量参数、参考图发送顺序与 SHA256，以及画布 / 节点 / 对话运行标识。未发送的可选参数记为 null 或省略，不推断供应商默认值。MCP 不提供优化前原文时，只能记录收到的工具提示词；浏览器原文沿用已有的本轮需求与引用上下文定义。

每次 HTTP 尝试有独立 requestId。`response` 事件只说明收到 HTTP 状态，不表示图片内容已经返回并保存；Responses 继承上一轮图像时也不伪记为重新上传参考图。日志不读取 Authorization / Key，不保存图片原文、参考图URL或上游完整错误消息；它包含私人提示词，应留在本机，不随分享包分发。日志故障不阻断生成，不引入额外生图重试。

### 文本对照结果

同一允许的语言模型配置、均衡档、temperature 0.6、8192输出预算，对海报、Logo和演示背景分别执行旧规则A / 新规则B各一次，共6次纯文本调用，没有新增生图。旧规则取修改前导出的完整 System Prompt；两组同题输入一致，不注入角色、Skill、长期偏好或参考图。原始需求、规则全文、哈希、输出与调用记录保存在本机 `experiments/rule-review-20261116`。

三类输出均通过现有数值保留与画幅检查。新版提示词从1222/407/394字符缩短为829/354/302字符，但这不是设计质量分数：海报仍出现常规红金与统一活动模块，Logo仍有多个未确定的形态和额外禁止项；背景减少了无关禁用项，保留了上方留白与水彩要求。样本不足以证明新版更好，也不能据此判断完整Agent路径、参考图理解或成图质量。

本轮未重构参考图模式与逐图角色的数据结构，未增加业务条件关系的语义校验，未全面审查动态角色 / Skill 注入，未增加自动重画或节点生成后视觉验收。这些仍是报告中的后续项。

## 验证与边界

回归覆盖两种文本协议、自动画幅传回实际请求与持久化、手动画幅、继续编辑、分辨率、复杂长提示词、数值与比例冲突，以及优化失败兜底。测试使用模拟上游和隔离数据目录，不消耗真实生图额度。

这些检查证明编排与参数传递的行为，不证明审美质量已经达到某个产品。实际效果需用相同模型、分辨率和输入对照，分别测试信息设计、Logo、场景插画、背景和编辑任务，同时评价需求准确性与视觉质量。
